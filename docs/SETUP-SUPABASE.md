# ตั้งค่าระบบห้องเรียน (Supabase)

ถ้ายังไม่ได้ตั้งค่า เกมจะทำงานใน **โหมดทดลอง**
- ครูลองใช้แดชบอร์ดได้ทันที แต่ข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้นเครื่องเดียว
- เหมาะสำหรับสาธิต ยังไม่เหมาะกับห้องเรียนจริง

ตั้งค่าตามขั้นตอนด้านล่างครั้งเดียว ใช้เวลาประมาณ 15 นาที แล้วข้อมูลจากทุกเครื่องจะรวมไว้ที่เดียว

## 1. สร้างโปรเจกต์
1. สมัครหรือเข้าสู่ระบบที่ https://supabase.com แล้วกด **New project**
2. ตั้งชื่อ เช่น `sanor-quest`
3. ตั้งรหัสผ่านฐานข้อมูลที่เดาได้ยาก แล้วเก็บไว้ (เกมไม่ได้ใช้รหัสนี้)
4. Region: เลือก **Southeast Asia (Singapore)** เพื่อให้เร็วที่สุดสำหรับประเทศไทย

## 2. สร้างตารางและกฎการเข้าถึง
1. ในโปรเจกต์ไปที่ **SQL Editor → New query**
2. คัดลอกทั้งไฟล์ `supabase/migrations/20261126000000_classroom.sql` ไปวาง แล้วกด **Run**
3. ต้องขึ้นว่า `Success. No rows returned`

ไฟล์นี้สร้างตาราง ห้องเรียน / นักเรียน / ผลการเล่น / แบบทดสอบ และตั้งกฎว่า
- ครูเห็นได้เฉพาะห้องของตัวเอง
- นักเรียนเขียนได้เฉพาะข้อมูลของตัวเอง
- คนทั่วไปเปิดอ่านตารางตรง ๆ ไม่ได้

## 3. ตั้งค่าการเข้าสู่ระบบของครู
1. ไปที่ **Authentication → Sign In / Providers → Email** แล้วเปิดใช้งาน
2. ช่วงทดลองปิด **Confirm email** ได้ เพื่อให้ครูเข้าใช้ได้ทันทีหลังสมัคร
3. ถ้าเปิด Confirm email ไว้ ครูต้องกดลิงก์ในอีเมลก่อนเข้าสู่ระบบ
4. ไปที่ **Authentication → URL Configuration** แล้วใส่ที่อยู่เว็บของเกม เช่น `https://<ชื่อผู้ใช้>.github.io/SANOR-Quest/`

## 4. ใส่ค่าการเชื่อมต่อในเกม
1. ไปที่ **Project Settings → API** แล้วคัดลอกสองค่า
   - **Project URL** เช่น `https://abcdefgh.supabase.co`
   - **anon public** key
2. เปิดไฟล์ `shared/config.js` แล้ววางทั้งสองค่า
   ```js
   window.SQ_CONFIG = {
     supabaseUrl: 'https://abcdefgh.supabase.co',
     supabaseAnonKey: 'eyJhbGciOi...'
   };
   ```
3. commit แล้ว push ขึ้น GitHub Pages

> anon key ออกแบบมาให้เปิดเผยได้ สิ่งที่คุมสิทธิ์คือกฎในข้อ 2
> **ห้ามใส่ `service_role` key ในเกมเด็ดขาด**

## 5. ทดลองใช้
1. ครูเปิด `.../teacher/` แล้ว **สมัครใช้งาน** → **สร้างห้อง** เพื่อรับรหัสห้อง 6 ตัว
2. นักเรียนเปิดเกม → ปุ่ม **🏫 Join my class** → ใส่รหัสห้อง, เลขที่, ชื่อเล่น และตั้ง PIN 4 หลัก
3. นักเรียนเล่นไปสักพัก แล้วครูกด **↻ รีเฟรช** ในแดชบอร์ด

## ค่าใช้จ่าย
- **ช่วงทดลอง 5 ห้อง ใช้แผน Free ได้** ข้อจำกัด: ถ้าไม่มีใครใช้ 7 วัน (เช่น ช่วงปิดเทอม) Supabase จะพักโปรเจกต์ ต้องเข้าไปกด Restore ข้อมูลไม่หาย
- **เมื่อใช้จริง 16 ห้อง แนะนำแผน Pro** ($25/เดือน ไม่มีการพักโปรเจกต์)

## ข้อมูลนักเรียนที่เก็บ (PDPA)
| เก็บ | ไม่เก็บ |
|---|---|
| เลขที่, ชื่อเล่นที่นักเรียนตั้งเอง, PIN (เก็บเป็นค่าแฮช), XP / ภารกิจ / คำตอบ / ผลการพูดแบบ ผ่าน/ไม่ผ่าน, คะแนนแบบทดสอบ | ชื่อจริง, อีเมลนักเรียน, รูป, ไฟล์เสียง |

- ครูลบนักเรียนพร้อมข้อมูลทั้งหมดได้ที่แดชบอร์ด → ดูรายละเอียด → **ลบนักเรียนออกจากห้อง**
- ถ้าลบห้อง ข้อมูลทั้งหมดในห้องจะถูกลบไปด้วย

## เมื่อนักเรียนลืม PIN
ครูเปิดแดชบอร์ด → **ดูรายละเอียด** ของนักเรียน → **ตั้ง PIN ใหม่** แล้วแจ้งนักเรียน ระบบจะออกจากระบบในเครื่องเดิมทั้งหมด

ถ้าใส่ PIN ผิด 5 ครั้ง ระบบจะล็อกไว้ 10 นาที หรือให้ครูตั้ง PIN ใหม่ก็ได้

## ทดสอบฐานข้อมูลโดยไม่ต้องมี Supabase
`npm test` จะรันไฟล์ SQL บน Postgres จำลอง (PGlite) และตรวจว่า
- กฎการเข้าถึงทำงานถูกต้อง
- การล็อก PIN ทำงาน
- การส่งข้อมูลซ้ำนับครั้งเดียว
- โหมดทดลองให้ผลเหมือนฐานข้อมูลจริง

ดูเทสต์ได้ที่ `tests/unit/db.spec.mjs` และ `backend-parity.spec.mjs`
