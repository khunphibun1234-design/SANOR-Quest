## 1. ตั้งโดเมน
ทุกลิงก์ในแอปเป็นแบบ relative จึงย้ายโดเมนได้โดยไม่ต้องแก้โค้ด

> ⚠️ **ตั้งโดเมนก่อนเริ่มทดลองรอบ 2** ความก้าวหน้าในเครื่อง (XP, แสตมป์, การตั้งค่า) ผูกกับที่อยู่เว็บ ถ้าเปลี่ยนโดเมนกลางคัน นักเรียนจะเห็นเกมเริ่มใหม่ในเครื่อง (ข้อมูลที่ส่งเข้าห้องเรียนแล้วยังอยู่ครบในแดชบอร์ดครู)

ทางเลือก
| แบบ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| ไม่ตั้งโดเมน | `https://<ชื่อผู้ใช้>.github.io/<repo>/` | ฟรี ใช้ได้ทันที แต่ยาวและจำยาก |
| โดเมนย่อยของโรงเรียน | `english.<โรงเรียน>.ac.th` | ขอฝ่าย IT ของโรงเรียนเพิ่มระเบียน CNAME ให้ |
| โดเมนของโครงการ | `sanorquest.com` หรือ `.in.th` | ซื้อรายปีจากผู้ให้บริการโดเมน (ตรวจราคาที่ผู้ให้บริการ) |

ขั้นตอน
1. ได้ชื่อโดเมนแล้วรัน
   ```bash
   node scripts/set-domain.js learn.sanorquest.com
   ```
   สคริปต์สร้างไฟล์ `CNAME` และพิมพ์ระเบียน DNS ที่ต้องเพิ่ม
2. เพิ่มระเบียน DNS ที่ผู้ให้บริการโดเมนตามที่สคริปต์บอก (โดเมนย่อยใช้ CNAME ชี้ไป `<ชื่อผู้ใช้>.github.io`)
3. commit ไฟล์ `CNAME` เข้า branch ที่ GitHub Pages ใช้เผยแพร่ (ดูได้ที่ GitHub → Settings → Pages)
4. GitHub → Settings → Pages → Custom domain ต้องขึ้นชื่อโดเมน รอ DNS check ผ่าน แล้วติ๊ก **Enforce HTTPS**
5. Supabase → Authentication → URL Configuration: เปลี่ยน **Site URL** และเพิ่ม **Redirect URLs** เป็นโดเมนใหม่
6. เปิดเว็บด้วยโดเมนใหม่ ลองเล่น 1 ภารกิจ และลองเข้าแดชบอร์ดครู

ยกเลิกโดเมน: `node scripts/set-domain.js --remove`

## 2. ระบบแจ้งเตือนเมื่อเกิด error
ทำงานอย่างไร
- ทุกหน้าโหลด `shared/errors.js` ซึ่งเก็บ error ที่เกิดในเบราว์เซอร์ของนักเรียนและครู (สูงสุด 5 รายการต่อหน้า) แล้วส่งเข้าตาราง `client_errors` ใน Supabase
- ข้อมูลที่ส่ง: หน้า, ข้อความ error (ตัดอีเมลและรหัสยาว ๆ ออก), ไฟล์และบรรทัด, เวอร์ชันแอป, ชนิดอุปกรณ์ เช่น `Android · Chrome 131` **ไม่มี**ชื่อเล่น คำตอบ หรือ token
- error เดียวกันในวันเดียวกันนับรวมเป็นแถวเดียว และเก็บได้ไม่เกิน 500 แบบต่อวัน
- GitHub Actions (`.github/workflows/health.yml`) ตรวจทุก 6 ชั่วโมง: เปิดหน้าและไฟล์หลัก 13 รายการ และดึง error ใน 6 ชั่วโมงล่าสุด ถ้ามีปัญหาจะเปิด issue ชื่อ "🚨 SANOR QUEST health alert" (label `health-alert`) GitHub จะส่งอีเมลถึงเจ้าของ repository ถ้าปัญหาเดิมยังอยู่จะไม่ส่งซ้ำ ปัญหาใหม่จะเพิ่มเป็นความคิดเห็น และเมื่อกลับมาปกติ issue จะปิดเอง

ตั้งค่า (ครั้งเดียว)
1. สร้างกุญแจลับสำหรับระบบตรวจ:
   ```bash
   openssl rand -hex 24
   ```
2. Supabase → SQL Editor รัน (แทน `กุญแจ` ด้วยค่าจากข้อ 1 · เก็บเฉพาะค่าแฮช):
   ```sql
   insert into public.ops_keys (key_hash, label) values (encode(sha256(convert_to('กุญแจ', 'UTF8')), 'hex'), 'github');
   ```
3. GitHub → Settings → Secrets and variables → Actions
   - **Secrets** → New repository secret: `HEALTH_KEY` = กุญแจจากข้อ 1
   - **Variables** (ไม่บังคับ): `SITE_URL` (ถ้าไม่ใส่ ใช้ไฟล์ CNAME หรือที่อยู่ github.io), `SUPABASE_URL` และ `SUPABASE_ANON_KEY` (ถ้าไม่ใส่ อ่านจาก `shared/config.js`)
4. ระบบตั้งเวลาทำงานจาก branch หลักของ repository เท่านั้น ให้ merge งานเข้า branch หลักก่อน
5. GitHub → Actions → **Health check** → **Run workflow** เพื่อทดสอบ
6. ตรวจว่า GitHub ส่งอีเมลเรื่อง issue: GitHub → Settings → Notifications → Email ต้องเปิดไว้ และกด Watch repository นี้

ตรวจด้วยมือบนเครื่อง: `npm run health` (ไม่เปิด issue)

ข้อควรรู้: GitHub หยุดงานตั้งเวลาเองถ้า repository ไม่มีความเคลื่อนไหว 60 วัน (จะมีอีเมลเตือนก่อน) กด Enable workflow อีกครั้งได้

### เมื่อได้รับแจ้งเตือน
| แจ้งว่า | ทำอะไร |
|---|---|
| `page /… HTTP 404/503` | เปิดหน้านั้นเอง · ดู GitHub → Actions ว่ามีการ deploy ล้มเหลวไหม · ดู githubstatus.com |
| `Supabase health_digest failed` | เปิด Supabase dashboard: โปรเจกต์ถูกพัก (Paused) ไหม ถ้าใช่กด Restore · ถ้าขึ้น `bad_key` ให้ตรวจ HEALTH_KEY |
| `error on /…` | เปิด issue ดูตาราง error (หน้า ข้อความ ตำแหน่ง อุปกรณ์) แล้วส่งให้ Claude แก้ · ดูรายการเต็มที่ `research/` → "ข้อผิดพลาดของระบบ" |

## 3. ผู้ประสานงานโครงการ (เห็นผลทุกโรงเรียน)
ผู้ประสานงานคือครูที่มีบัญชีในแดชบอร์ดครูแล้ว และถูกเพิ่มในตาราง `coordinators`
```sql
insert into public.coordinators (id) select id from auth.users where email = 'อีเมลของผู้ประสานงาน';
```
จากนั้นเปิด `research/` (ใช้บัญชีเดียวกับแดชบอร์ดครู) จะเห็น
- ภาพรวมทุกโรงเรียน: จำนวนนักเรียน การเล่นใน 7 วัน เวลาเล่นจริง คำตอบถูกตั้งแต่ครั้งแรก
- ผลก่อน/หลังเรียนรายโรงเรียนและรายห้อง: คะแนนเพิ่มขึ้น ช่วงความเชื่อมั่น 95% ขนาดผล dz และค่า p
- ร้อยละที่จบแต่ละโลก ความเห็นนักเรียน และ error 7 วันล่าสุด
- เกณฑ์ความพร้อมเปิดใช้งาน 6 ข้อ (ปรับตัวเลขได้ใน `research/analysis.js` → `CRITERIA`)

ข้อมูลในหน้านี้ไม่มีชื่อเล่นหรือเลขที่ของนักเรียน โรงเรียนจัดกลุ่มตามชื่อโรงเรียนที่ครูพิมพ์ตอนสมัคร จึงควรให้ครูทุกคนในโรงเรียนเดียวกันพิมพ์ชื่อโรงเรียนให้ตรงกัน

## 4. หน้าเว็บสำหรับครูและผู้บริหาร (`schools/`)
- อธิบายว่าแอปทำอะไรได้ แสดง 6 โลกพร้อมภาพจริงจากเกม เครื่องมือครู ความเป็นส่วนตัว วิธีเริ่มใช้ และคำถามที่พบบ่อย
- พิมพ์เป็นเอกสารแนะนำได้ (ปุ่มท้ายหน้า)
- **ผลการทดลอง** มาจาก `schools/results.js`: ที่ `research/` กด "ส่งออกผลสำหรับหน้าเว็บโรงเรียน" → ดาวน์โหลด → วางทับไฟล์แล้ว push
  - ไม่มีชื่อโรงเรียน (ใช้ โรงเรียน A, B, C) ไม่แสดงกลุ่มที่มีนักเรียนน้อยกว่า 10 คน
  - ผลก่อน/หลังเรียนแสดงเมื่อมีนักเรียนครบคู่อย่างน้อย 20 คน ก่อนหน้านั้นหน้าเว็บจะบอกว่า "กำลังดำเนินการ"
- ภาพโลกอยู่ที่ `images/worlds/` ถ้าฉากเปลี่ยนมาก ให้ถ่ายใหม่ขนาด 820×580
