## ตรวจผลจากข้อมูลจริงทุกสัปดาห์ (ผู้ประสานงานโครงการ · วันศุกร์)
1. เปิด `research/` → กด **ดาวน์โหลด CSV** เก็บไว้เป็นหลักฐานรายสัปดาห์
2. ดู 4 อย่างนี้ตามลำดับ
   1. **ข้อผิดพลาดของระบบ:** อะไรที่เกิดซ้ำหลายครั้ง หรือเกิดกับอุปกรณ์รุ่นเดียวกันหลายเครื่อง
   2. **เล่นใน 7 วันล่าสุด:** โรงเรียนหรือห้องที่ต่ำกว่า 60% → ติดต่อผู้ประสานงานของโรงเรียน
   3. **การเล่นในแต่ละโลก:** โลกที่นักเรียนเริ่มแต่ไม่จบ → ให้ครูห้องนั้นดูแท็บ "การทดลอง" ว่าติดคำถามไหน
   4. **ความคิดเห็นของนักเรียน:** ความสนุกหรือความง่ายต่ำกว่า 2.0 ในโลกใด
3. ส่งให้ Claude: CSV จาก `research/` + CSV ของแท็บ "การทดลอง" จากครูที่มีปัญหา + issue แจ้งเตือน (ถ้ามี) → แก้ไขและส่งเวอร์ชันใหม่ก่อนวันจันทร์ (เกมอัปเดตเองบนเครื่องนักเรียน)
4. บันทึกทุกการแก้ไขใน `docs/PILOT-LOG.md`

## ตัดสินใจเปิดใช้งาน (หลังสัปดาห์ 6)
ใช้ "เกณฑ์ความพร้อมเปิดใช้งาน" ในหน้า `research/` (เกณฑ์ที่เสนอ ปรับได้ใน `research/analysis.js`)
| เกณฑ์ | เป้า |
|---|---|
| จำนวนโรงเรียนที่ทดลอง | ≥ 3 |
| นักเรียนที่ทำแบบทดสอบครบทั้งก่อนและหลัง | ≥ 60% |
| คะแนนก่อน → หลัง | เพิ่มขึ้นอย่างมีนัยสำคัญ (p < .05) และ dz ≥ 0.5 |
| จบภารกิจแรกของ Map 01 | ≥ 70% |
| ความสนุกเฉลี่ย | ≥ 2.3 จาก 3 |
| error ที่เกิดซ้ำเกิน 20 ครั้งใน 7 วันล่าสุด | ไม่มี |

ผ่านครบ → ส่งออกผลไปหน้า `schools/` (`docs/LAUNCH.md` ข้อ 4) และเปิดรับโรงเรียนใหม่ · ไม่ผ่าน → แก้ตามข้อมูลแล้วทดลองต่ออีก 2–3 สัปดาห์ในโรงเรียนเดิม
