## ข้อมูลที่ระบบเก็บให้อัตโนมัติ (แดชบอร์ด → แท็บ "การทดลอง")
| เรื่อง | มาจาก |
|---|---|
| **เวลาที่เล่นจริง** รายคน รายสัปดาห์ รายภารกิจ | นับเฉพาะตอนที่หน้าจอเปิดและนักเรียนเล่นอยู่ |
| **จุดที่ติดหรือเลิกเล่น** | ทุกคำถามบันทึกว่า "เปิด" และ "ผ่าน" กี่คน · 5 จุดที่ผ่านน้อยที่สุด |
| **คำที่ผิดบ่อย** | แท็บ "คำที่พลาดบ่อย" (คำตอบครั้งแรก) |

| **ความเห็นครู** | "บันทึกของครูรายสัปดาห์" ในแท็บเดียวกัน |
| **ก่อน/หลังเรียน** | paired t-test และขนาดผล (Cohen's dz) คำนวณให้ |

## รอบแก้ไขรายสัปดาห์
1. **วันศุกร์:** ครูกรอกบันทึกรายสัปดาห์ แล้วกด ⬇ ข้อมูลการทดลอง (CSV) และ ⬇ ความเห็นนักเรียน (CSV)
2. **ส่งให้ Claude:** ไฟล์ CSV ทั้งสอง + รูปแบบสังเกต (ถ่ายรูปได้) + เรื่องที่ครูอยากให้แก้
3. **Claude วิเคราะห์และแก้** ตามลำดับนี้:
   1. ปัญหาที่ทำให้เล่นต่อไม่ได้
   2. จุดที่ผ่านต่ำกว่า 60%
   3. คำ/ประโยคที่ผิดเกิน 50%
   4. ความเห็นที่ซ้ำกันหลายคน
4. **ส่งเวอร์ชันใหม่ก่อนวันจันทร์:** เกมอัปเดตเองบนเครื่องนักเรียน (PWA)
5. **ทุกการแก้ไขบันทึกใน `docs/PILOT-LOG.md`:** อะไรเปลี่ยน เพราะข้อมูลอะไร

## เกณฑ์ว่า "พร้อมขยาย" (ใช้ตัดสินหลังสัปดาห์ 4)
| เกณฑ์ | เป้า |
|---|---|
| นักเรียนจบ Map 01–02 ครบ 6 ภารกิจ | ≥ 70% |
| เวลาเล่นจริงเฉลี่ย | ≥ 90 นาทีใน 4 สัปดาห์ |
| ทุกคำถามมีอัตราผ่าน | ≥ 60% |
| ความเห็นเฉลี่ย "สนุก" | ≥ 2.3 จาก 3 |
| คะแนนก่อน → หลัง | เพิ่มขึ้นอย่างมีนัยสำคัญ (p < .05) และ dz ≥ 0.5 |
| ปัญหาที่ทำให้เล่นต่อไม่ได้ (เกมค้าง/ข้อมูลหาย) ในสัปดาห์สุดท้าย | 0 |

## ข้อควรระวังในการตีความ
- **ข้อสอบก่อนและหลังเป็นชุดเดียวกัน** (สลับลำดับ) คะแนนหลังเรียนอาจสูงขึ้นบางส่วนเพราะเคยเห็นข้อสอบ
- **ไม่มีห้องเปรียบเทียบ** ถ้าต้องการหลักฐานที่หนักแน่นขึ้น ให้เทียบกับห้องที่เรียนแบบปกติในรอบ 2 (ระยะ 9)
- **ข้อมูลทั้งหมดเป็นนามแฝง** (เลขที่ + ชื่อเล่น) อย่าเผยแพร่ไฟล์ CSV นอกทีมวิจัย/ครู
